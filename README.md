# Repair Bot — Telegram-бот приёма заявок на ремонт

Реализация ТЗ «Telegram-система приёма и обработки заявок на ремонт»
на стеке: Telegraf (Node.js) + Google Sheets API (сервисный аккаунт) + Vercel (serverless).

## Структура проекта

```
api/webhook.js       — точка входа serverless-функции Vercel, принимает апдейты от Telegram
src/bot.js            — вся логика бота: диалог клиента (сцена), кнопки сотрудника
src/sheetsClient.js   — низкоуровневый клиент Google Sheets API (авторизация, чтение/запись строк)
src/requests.js       — работа с листом "Заявки"
src/employees.js      — работа с листом "Сотрудники"
src/sessionStore.js   — хранение состояния диалога (FSM) в листе "Sessions" (нужно для serverless)
scripts/initSheets.js — разово создаёт листы и заголовки в таблице
scripts/setWebhook.js — прописывает Telegram webhook на задеплоенный URL
localDev.js           — локальный запуск через long polling (для разработки)
```

## 1. Подготовка

### 1.1. Бот в Telegram

Создайте бота через [@BotFather](https://t.me/BotFather), получите `BOT_TOKEN`.

### 1.2. Google Cloud — сервисный аккаунт

1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/).
2. Включите **Google Sheets API**.
3. Создайте сервисный аккаунт (Service Account), скачайте JSON-ключ.
4. Из JSON возьмите `client_email` → это `GOOGLE_SERVICE_ACCOUNT_EMAIL`,
   и `private_key` → это `GOOGLE_PRIVATE_KEY`.
   Если удобнее хранить ключ в отдельном файле, можно вместо этого указать
   `GOOGLE_APPLICATION_CREDENTIALS` на путь к JSON-файлу сервисного аккаунта.

### 1.3. Google-таблица

1. Создайте новую Google Таблицу, скопируйте её ID из URL (между `/d/` и `/edit`) → `SPREADSHEET_ID`.
2. **Откройте доступ** к таблице для email сервисного аккаунта (роль — Редактор).
3. Заполните `.env` (скопируйте `.env.example`) и выполните:
   ```
   npm install
   npm run init-sheets
   ```
   Скрипт создаст листы «Заявки», «Сотрудники», «Database», «Sessions» и «Оплата та розрахунки» с заголовками.
4. В листе **«Database»** добавьте активные города (`да` в колонке «Активен (да/нет)»),
   а также категории в колонку «Список категорий» и их коды в «Код категории».
5. В листе **«Сотрудники»** вручную добавьте сотрудников: их Telegram ID, имя,
   категорию и `да` в колонке «Активен».
   Telegram ID сотрудника можно узнать, попросив его написать боту [@userinfobot](https://t.me/userinfobot).

## 2. Деплой на Vercel

1. Залейте проект в свой git-репозиторий, подключите его к Vercel (или используйте `vercel` CLI).
2. В настройках проекта на Vercel добавьте переменные окружения:
   `BOT_TOKEN`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `SPREADSHEET_ID`, `WEBHOOK_SECRET`.
   (`GOOGLE_PRIVATE_KEY` вставляйте с `\n` вместо переносов строк, как в `.env.example`.)
3. Задеплойте проект (`vercel --prod` либо через git push).
4. Пропишите Telegram webhook на полученный URL:
   ```
   PUBLIC_URL=https://ваш-проект.vercel.app npm run set-webhook
   ```
   либо вручную:
   ```
   curl -X POST "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
     -H "Content-Type: application/json" \
     -d '{"url":"https://ваш-проект.vercel.app/api/webhook?secret=<WEBHOOK_SECRET>"}'
   ```

Готово — бот работает через webhook, отдельного постоянно запущенного сервера не требуется.

## 3. Локальная разработка

```
cp .env.example .env    # и заполните значениями
npm install
npm run dev              # запуск через long polling, без Vercel и webhook
```

## 4. Логика работы (кратко)

- Клиент нажимает «Оставить заявку» → проходит пошаговый диалог (категория → описание →
  адрес → удобное время → телефон) → заявка сохраняется в лист «Заявки» со статусом
  «Получена от клиента».
- Всем активным сотрудникам выбранной категории одновременно приходит уведомление
  с кнопкой «Взять в работу».
- Кто первый нажал кнопку — тот и получает заявку (статус → «Взята в работу»,
  остальным сотрудникам сообщение помечается как неактуальное). Есть защита от гонки:
  перед назначением бот перепроверяет текущий статус заявки в таблице.
- Сотрудник, взявший заявку, далее нажимает «Выехал на место» и «Закрыть заявку» —
  статусы меняются последовательно. Также доступна кнопка «Отказаться от заявки» —
  она возвращает заявку в общий пул и рассылку остальным сотрудникам категории.
- Клиент на каждом изменении статуса получает уведомление в Telegram.

## 5. Что стоит донастроить перед продакшеном

- Ограничить логи (сейчас ошибки просто пишутся в `console.error` — на Vercel это попадает
  в Logs проекта, для истории дольше суток нужен внешний сборщик логов).
- При заметном росте числа заявок в день — рассмотреть замену Google Sheets на полноценную
  БД (Postgres/Airtable); слой `src/requests.js` и `src/employees.js` спроектирован так,
  чтобы это можно было сделать без переписывания `src/bot.js`.
- Опционально — простая команда для администратора на добавление сотрудника прямо из бота
  (сейчас это делается вручную в таблице).
